Build decisions I made when Claude Code asked (2026-11-25):
- **Filter numbers:** follow FILTER.md, keep at score ≥ 5 with close calls at 4–5. The build
  instructions had said ≥ 4.
- **`close_call`:** only for score-decided postings, with no exclusion and a description present.
- **Set A sampling:**
  - close calls are a seeded random draw
  - KEPT postings are drawn before close calls
  - all 4 KEPT postings were taken when 5 didn't exist
- **v3:**
  - X3 reads the location field, then the description's "Available Location(s)" line
  - the X5 regex is used literally
  - CANNOT_TELL only when the missing field could change the outcome to KEPT
  - the new rule set is named v3, and v1/v2 are kept
- **Score report:** Change 1 is threshold 5 → 4, and Change 2 compares filter v2 with v1 as they
  are.
